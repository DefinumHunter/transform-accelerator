# pe_output_strapping

Выходная ступень процессорного элемента. Берёт произведение своего MAC и бегущую сумму от левого соседа, складывает их (или вычитает своё произведение), насыщает и отправляет результат дальше: либо следующему PE по кольцу, либо наружу из массива как готовый.

## Что считает

| `sub_post` | Результат |
|---|---|
| 0 | `out = sat(neighbor_res + mac_res)` |
| 1 | `out = sat(neighbor_res - mac_res)` |

`sat` — насыщение до 32 бит со знаком. Сосед прибавляется всегда, режима «без соседа» нет. У первого PE в цепочке соседа нет, и на `neighbor_res` подаётся 0.

| `ring_final` | Куда идёт результат |
|---|---|
| 1 | следующему PE: `out_valid_ring = 1` |
| 0 | наружу из массива: `out_valid_final = 1` |

## Параметр

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `CHECK_NEIGHBOR` | 1 | проверять, что сосед прислал результат той же транзакции. У первого PE цепочки ставится 0 |

## Порты

| Порт | Направление | Ширина | Откуда / куда |
|---|---|---|---|
| `clk`, `rst_n` | вход | 1 | такт, синхронный сброс активным 0 |
| `mac_res` | вход | 32, со знаком | `mac_q16.out_res` своего PE |
| `mac_vld` | вход | 1 | `mac_q16.out_vld` |
| `mac_id` | вход | 4 | `mac_q16.out_id` |
| `mac_ring_final`, `mac_sub_post` | вход | 1 | `mac_q16.out_ring_final`, `out_sub_post` |
| `neighbor_res` | вход | 32, со знаком | `out` левого соседа (у первого PE — 0) |
| `neighbor_vld` | вход | 1 | `out_valid_ring` левого соседа |
| `neighbor_id` | вход | 4 | `out_id` левого соседа |
| `out` | выход | 32, со знаком | результат |
| `out_id` | выход | 4 | id результата (это `mac_id`) |
| `out_valid_ring` | выход | 1 | результат для следующего PE |
| `out_valid_final` | выход | 1 | готовый результат наружу |
| `idle` | выход | 1 | внутри нет ни одного результата. Комбинационный |
| `error` | выход | 1 | была ошибка стыковки с соседом. Держится до сброса |

## Проверка соседа

При `CHECK_NEIGHBOR = 1` каждое произведение (`mac_vld = 1`) должно прийти в одном такте с результатом соседа (`neighbor_vld = 1`) с тем же id (`neighbor_id == mac_id`). Если это не так:

- произведение выбрасывается: результата на выходе не будет;
- `error` становится 1 и держится до сброса.

В тактах без произведения (`mac_vld = 0`) сосед не проверяется: что бы он ни присылал, ошибки нет.

При `CHECK_NEIGHBOR = 0` входы `neighbor_vld` и `neighbor_id` не используются.

## Задержка

Результат выходит **через 2 такта после такта с `mac_vld = 1`**: `out`, `out_id` и один из двух valid одновременно. Новое произведение может приходить каждый такт.

## Как устроен внутри

| Ступень | Регистры | Когда пишутся |
|---|---|---|
| ступень 1 | `mac_reg`, `neighbor_reg`, `id_reg`, `ring_reg`, `sub_reg` | каждый такт |
| ступень 1 | `valid_reg` | каждый такт: `mac_vld`, если сосед прошёл проверку, иначе 0 |
| ступень 1 | `error` | ставится в 1 при неудачной проверке, сбрасывается только сбросом |
| между ступенями | `neighbor ± mac` с насыщением | комбинационно |
| ступень 2 | `out`, `out_id` | каждый такт |
| ступень 2 | `out_valid_ring`, `out_valid_final` | каждый такт, из `valid_reg` и `ring_reg` |

## Сброс

| Что | При сбросе |
|---|---|
| `valid_reg`, `out_valid_ring`, `out_valid_final`, `error` | 0 |
| `out`, `out_id` и регистры данных | не сбрасываются: читать их имеет смысл только при одном из valid = 1 |

## Что изменилось по сравнению со старой версией

| Было | Стало | Зачем |
|---|---|---|
| всегда `mac + neighbor` | `neighbor + mac` или `neighbor - mac` по `sub_post` | `sub_post` из команды теперь работает |
| id сравнивался каждый такт, даже без операции | только при `mac_vld = 1` | в пустых тактах возникали ложные ошибки |
| valid соседа не проверялся | вход `neighbor_vld`, проверяется вместе с id | не складывать с соседом, у которого результата нет |
| у первого PE проверка id давала ошибку | параметр `CHECK_NEIGHBOR = 0` | у первого PE соседа нет |
| `sel`, `in_valid`, `in_id_self`, `in_id_neighbor` | `mac_ring_final`, `mac_vld`, `mac_id`, `neighbor_id` | имена говорят, откуда сигнал |
| — | `mac_sub_post`, `neighbor_vld` | новые входы |

Выходы не переименованы, чтобы не трогать `array_output_router`.

## Проверено

В Icarus с `CHECK_NEIGHBOR` = 1 и 0, 3000 тактов на каждый, со случайными ошибками стыковки и сбросом посреди потока. Ожидаемые значения считались независимо от RTL: 0 ошибок в данных, id, обоих valid и `error`.

## Открытый вопрос для массива

Strapping складывает своё произведение с тем, что сосед выдаёт **в том же такте**. Значит, в массиве произведение PE номер k должно выходить из MAC ровно тогда, когда левый сосед выдаёт свою сумму с тем же id. Как именно выравниваются такты между соседями, решается в архитектуре массива (задержкой подачи команды на каждый следующий PE), а не здесь. Если выравнивания не будет, сработает `error`.
