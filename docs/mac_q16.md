# mac_q16

Умножитель процессорного элемента. Перемножает два числа Q16.16, округляет результат к ближайшему (половину — к чётному) и насыщает до 32 бит со знаком. Id транзакции и два флага команды едут через конвейер вместе с valid и выходят в том же такте, что и результат.

## Что считает

`out_res = sat(round(in_a * in_b / 2^16))`

| Шаг | Правило |
|---|---|
| умножение | 32 × 32 бит со знаком, полное 64-битное произведение |
| округление | отбрасываются младшие 16 бит. Остаток больше половины младшего разряда — вверх, меньше — вниз, ровно половина — к чётному |
| насыщение | больше `0x7FFFFFFF` → `0x7FFFFFFF`, меньше `0x80000000` → `0x80000000` |

Примеры (в Q16.16 число `x` записывается как `x * 65536`):

| `in_a` | `in_b` | `out_res` | Почему |
|---|---|---|---|
| 3.0 | 2.5 | 7.5 | обычный случай |
| `1` (младший разряд) | 0.5 | 0 | ровно половина, 0 чётный: остаётся 0 |
| `3` | 0.5 | `2` | 1.5 разряда: ровно половина, к чётному 2 |
| `0x7FFFFFFF` | `0x7FFFFFFF` | `0x7FFFFFFF` | переполнение вверх |
| `0x80000000` | `0x7FFFFFFF` | `0x80000000` | переполнение вниз |

## Параметр

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `PIPELINE_STAGES` | 4 | число регистров конвейера, оно же задержка в тактах (не меньше 1) |

## Порты

| Порт | Направление | Ширина | Что это |
|---|---|---|---|
| `clk`, `rst_n` | вход | 1 | такт, синхронный сброс активным 0 |
| `in_vld` | вход | 1 | на входах лежит операция |
| `in_a`, `in_b` | вход | 32, со знаком | множители, Q16.16 |
| `in_id` | вход | 4 | номер транзакции, проходит насквозь |
| `in_ring_final`, `in_sub_post` | вход | 1 | флаги для `pe_output_strapping`, проходят насквозь |
| `out_vld` | выход | 1 | на выходах результат операции |
| `out_res` | выход | 32, со знаком | произведение, Q16.16 |
| `out_id`, `out_ring_final`, `out_sub_post` | выход | 4, 1, 1 | id и флаги этой операции |
| `busy` | выход | 1 | в MAC есть операция: на входе или в конвейере. Комбинационный |

Входы подключаются к выходам `pe_input_mux` один к одному: `a_out` → `in_a`, `b_out` → `in_b`, `out_vld` → `in_vld`, `out_id` → `in_id`, `out_ring_final` → `in_ring_final`, `out_sub_post` → `in_sub_post`.

## Протокол и задержка

- Новая операция может приходить каждый такт.
- Результат выходит **через `PIPELINE_STAGES` тактов после такта с `in_vld = 1`**: `out_res`, `out_vld`, `out_id` и флаги одновременно.
- При `in_vld = 0` данные всё равно проходят по конвейеру, но на выходе `out_vld = 0`, и смотреть на них не надо.

## Как устроен внутри

| Часть | Что делает |
|---|---|
| `pipe[0..N-1]` | 64-битное произведение, сдвигается каждый такт |
| `vld_pipe[0..N-1]` | valid, сдвигается каждый такт |
| `side_pipe[0..N-1]` | `{id, ring_final, sub_post}`, 6 бит, сдвигается каждый такт |
| округление и насыщение | комбинационно, из последней ступени `pipe` |

Умножение — на входе, комбинационно, перед первым регистром. Округление и насыщение — на выходе, комбинационно, после последнего. Поэтому синтезатор может перенести умножение по ступеням конвейера (retiming).

## Сброс

| Что | При сбросе |
|---|---|
| `vld_pipe` | 0, значит `out_vld = 0` и `busy` зависит только от `in_vld` |
| `pipe`, `side_pipe` | не сбрасываются: их читают только при `out_vld = 1` |

После сброса `out_res`, `out_id` и флаги могут быть X, пока не выйдет первая операция. Golden должен показывать там X (`None`).

## Что изменилось по сравнению со старой версией

| Было | Стало | Зачем |
|---|---|---|
| один боковой бит `sel` → `out_sel` | `in_id`, `in_ring_final`, `in_sub_post` → `out_id`, `out_ring_final`, `out_sub_post` | strapping должен получить id и оба флага своей операции |
| `sel_pipe` сбрасывался | `side_pipe` не сбрасывается | читается только вместе с valid, сброс не нужен |

## Проверено

В Icarus при `PIPELINE_STAGES` = 1, 4 и 7, больше 6000 произведений, включая граничные значения и точные половины разряда. Ожидаемые значения считались независимо, точной арифметикой с дробями, а не повторением логики RTL: 0 ошибок, задержка ровно `PIPELINE_STAGES`, id и флаги совпадают.
