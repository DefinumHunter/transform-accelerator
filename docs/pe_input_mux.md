# pe_input_mux

Входная ступень процессорного элемента. Выбирает два операнда для `mac_q16` (при необходимости сначала складывает или вычитает пару чисел с насыщением) и передаёт их в MAC вместе с valid, id и двумя флагами команды.

## Что умеет

| Операция | Что уходит в MAC | Тактов на входе |
|---|---|---|
| `a * b` | `a`, `b` | 1 |
| `a * local` | `a`, `local_data` | 1 |
| `(a + b) * c` | `c`, `sat(a + b)` | 2 |
| `(a - b) * c` | `c`, `sat(a - b)` | 2 |

`sat` — насыщение до 32 бит со знаком: результат больше `0x7FFFFFFF` становится `0x7FFFFFFF`, меньше `0x80000000` становится `0x80000000`.

## Порты

| Порт | Направление | Ширина | Что это |
|---|---|---|---|
| `clk`, `rst_n` | вход | 1 | такт, синхронный сброс активным 0 |
| `in_a`, `in_b` | вход | 32, со знаком | операнды |
| `local_data` | вход | 32, со знаком | локальное значение PE |
| `sel` | вход | 2 | что делать в этом такте (таблица ниже) |
| `sub_pre` | вход | 1 | для предсуммы: 0 = `a + b`, 1 = `a - b` |
| `issue_vld` | вход | 1 | операция собрана, отправить её в MAC |
| `in_id` | вход | 4 | номер транзакции |
| `ring_final` | вход | 1 | флаг для `pe_output_strapping`, проходит насквозь |
| `sub_post` | вход | 1 | флаг для `pe_output_strapping`, проходит насквозь |
| `a_out`, `b_out` | выход | 32, со знаком | операнды для MAC |
| `out_vld` | выход | 1 | на `a_out`/`b_out` лежит операция |
| `out_id` | выход | 4 | номер этой операции |
| `out_ring_final`, `out_sub_post` | выход | 1 | флаги этой операции |

## Значения `sel`

| `sel` | Имя | Что делает |
|---|---|---|
| `00` | `SEL_AB` | операнды = `in_a`, `in_b` |
| `01` | `SEL_SUM` | запомнить `in_a`, `in_b` для предсуммы; операнды не трогать |
| `10` | `SEL_SUM_C` | операнды = `in_a` (это `c`), `sat(сумма ± разность)` |
| `11` | `SEL_LOCAL` | операнды = `in_a`, `local_data` |

## Протокол

Главное правило: **`issue_vld = 1` подаётся в такте последней загрузки операции**. В этом же такте берутся `in_id`, `ring_final` и `sub_post`.

| Операция | Такт 1 | Такт 2 |
|---|---|---|
| `a * b` | `sel=00`, `in_a=a`, `in_b=b`, `issue_vld=1` | — |
| `a * local` | `sel=11`, `in_a=a`, `local_data=l`, `issue_vld=1` | — |
| `(a ± b) * c` | `sel=01`, `in_a=a`, `in_b=b`, `sub_pre=±` | `sel=10`, `in_a=c`, `sub_pre=±`, `issue_vld=1` |

- `sub_pre` должен держать одно значение оба такта операции с суммой: разность считается во втором такте.
- Операции можно подавать вплотную: следующая начинается в такте сразу после `issue_vld` предыдущей. Полная скорость — одна операция за такт (для `a*b` и `a*local`) или за два такта (для суммы).
- В такте без операции: `sel=01`, `issue_vld=0`. Это ничего не портит: перезаписываются только регистры предсуммы, а их каждая операция с суммой загружает сама.

## Задержка

Результат выходит **через 2 такта после такта с `issue_vld`**: данные, `out_vld`, `out_id` и оба флага появляются одновременно.

Пример: четыре операции подряд (проверено в Icarus).

| Такт | Вход | Выход |
|---|---|---|
| 2 | `a*b`: 3, 5, id 1, `issue_vld` | — |
| 3 | сумма, такт 1: 10, 20 | — |
| 4 | сумма, такт 2: `c` = 7, id 2, `issue_vld` | `out_vld=1`: 3, 5, id 1 |
| 5 | `a*local`: 9, 11, id 3, `issue_vld` | — |
| 6 | — | `out_vld=1`: 7, 30, id 2 |
| 7 | — | `out_vld=1`: 9, 11, id 3 |

## Как устроен внутри

Две ступени регистров. Данные и valid проходят **обе**, поэтому выходят вместе.

| Ступень | Регистры | Когда пишутся |
|---|---|---|
| предсумма | `sum1_reg`, `sum2_reg` | при `sel=01` |
| ступень 1 | `op1_reg`, `op2_reg` | при `sel=00`, `10`, `11` |
| ступень 1 | `vld_reg` | каждый такт, копия `issue_vld` |
| ступень 1 | `id_reg`, `ring_reg`, `subpost_reg` | при `issue_vld=1` |
| ступень 2 | `a_out`, `b_out` | каждый такт, из `op1_reg`, `op2_reg` |
| ступень 2 | `out_vld` | каждый такт, из `vld_reg` |
| ступень 2 | `out_id`, `out_ring_final`, `out_sub_post` | при `vld_reg=1` |

Сумма `sum1 ± sum2` считается комбинационно из регистров предсуммы и записывается в `op2_reg` во втором такте операции.

## Сброс

| Что | При сбросе |
|---|---|
| `out_vld`, `vld_reg` | 0 |
| `sum1_reg`, `sum2_reg`, `op1_reg`, `op2_reg` | 0 |
| `id_reg`, флаги, `a_out`, `b_out`, `out_id`, `out_ring_final`, `out_sub_post` | не сбрасываются: читать их имеет смысл только при `out_vld=1`, а он после сброса 0 |

После сброса выходы данных и флагов могут быть X, пока не пройдёт первая операция. Golden должен показывать там X (`None`), а не 0.

## Что изменилось по сравнению со старой версией

| Было | Стало | Зачем |
|---|---|---|
| valid проходил 1 регистр, данные 2 | оба проходят 2 | valid обгонял данные на такт: в MAC уходили операнды предыдущей операции |
| `sub` | `sub_pre` | имя как у выхода `cmd_parser`, чтобы соединять без путаницы |
| id 5 бит | id 4 бита | как в `pe_output_strapping` |
| id писался при загрузке (`sel`) | id пишется при `issue_vld` | вместе с флагами, по одному правилу |
| `ring_final`, `sub_post` шли мимо | идут через mux вместе с операцией | strapping должен получить флаги своей операции |
| `compare_id` | убран | не использовался |
| — | порты `ring_final`, `sub_post`, `out_ring_final`, `out_sub_post` | новые |

## Что ещё надо согласовать с соседями

- **`mac_q16`** должен протащить через свой конвейер `out_id` и оба флага. Сейчас у него один боковой бит (`sel` → `out_sel`) и нет id.
- **`pe_output_strapping`** не умеет вычитать: `sub_post` ему пока некуда подать.
- **`cmd_parser`** уже работает по этому протоколу (выдача в такте последней загрузки), менять его не нужно.
